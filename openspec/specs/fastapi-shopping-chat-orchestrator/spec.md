## Purpose
Define requirements for the FastAPI shopping chat orchestrator that replaces the previous chatbot runtime while preserving frontend action compatibility.

## Requirements

### Requirement: FastAPI chatbot endpoint SHALL orchestrate shopping conversation
The system SHALL expose a FastAPI chatbot endpoint that receives user message and short-turn context, then returns assistant reply and executable actions for the frontend chat UI.

#### Scenario: Respond to normal shopping message
- **WHEN** a user sends a Vietnamese shopping message to the chatbot endpoint
- **THEN** the endpoint returns a structured response containing reply text, next context, and zero or more actions

### Requirement: Chat orchestration SHALL support four core shopping intents
The system SHALL detect and handle product search, budget-based recommendation, persuasive product explanation, and add-to-cart guidance as first-class intents in one conversation flow.

#### Scenario: Detect and route shopping intent
- **WHEN** the user asks for product suggestions with or without explicit budget
- **THEN** the orchestrator routes the request to the appropriate intent branch and returns relevant recommendation actions

### Requirement: Orchestrator SHALL enforce purchase detail state transitions
The system SHALL keep conversation state so add-to-cart flow cannot complete until required details are collected: confirmed product, selected variant (if needed), and quantity.

#### Scenario: User confirms product but details are incomplete
- **WHEN** user confirms they want to buy but has not selected variant or quantity yet
- **THEN** orchestrator transitions to the next missing-detail question instead of emitting add-to-cart action

### Requirement: Chatbot responses SHALL be Vietnamese-first and low-latency
The system SHALL prioritize Vietnamese reply generation and enforce timeout/fallback behavior to keep response speed suitable for live shopping assistance.

#### Scenario: AI provider delay
- **WHEN** Gemini response exceeds configured timeout or fails transiently
- **THEN** the system returns a safe fallback response generated by deterministic rules without blocking the chat session

### Requirement: Chatbot runtime SHALL be replaceable without changing chat UI structure
The system SHALL preserve action-driven response compatibility required by the existing frontend chat UX so chatbot backend can be replaced without redesigning chat components.

#### Scenario: Frontend compatibility
- **WHEN** frontend renders chatbot response from FastAPI
- **THEN** existing UI components can render text and actions without requiring a visual redesign
